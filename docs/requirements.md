# Требования к помощнику по собеседованиям

Дата: 15 ноября 2026 года. Статус: черновик для совместного обсуждения.

Этот документ фиксирует договорённости и предложения по продукту. Наличие
предложения в документе не означает согласования его реализации.
План работ: [tasks.md](tasks.md).

## Подтверждено владельцем проекта

- Это дипломный проект: помощник для разбора собеседований.
- Пользователь загружает запись длительностью примерно час.
- Запись преобразуется в текст, затем текст анализирует языковая модель.
- Результат должен включать разбиение собеседования на темы и вопросы,
  оценки ответов, подборку заданных вопросов и проблемных мест.
- На основе проблемных мест нужны похожие вопросы для подготовки.
- Требования и задачи обсуждаем совместно. Разработку ведёт ассистент
  под руководством владельца проекта.
- Сейчас работаем над требованиями; реализацию функций ещё не начинаем.

## Что уже есть в репозитории

По чтению кода, без проверки запуском:

- Java/Spring Boot API для загрузки файла и получения статуса.
- Сохранение файлов на диск и метаданных в PostgreSQL, миграции Liquibase.
- Фоновое извлечение аудио через FFmpeg.
- Python/FastAPI с faster-whisper: русская расшифровка, временные метки,
  коррекция терминов Java-разработки.
- Сохранение расшифровки и ошибок обработки.
- Сущности интервью и вопросов с полями для оценок и замечаний.
- Тесты Java и конфигурация CI.

Анализ ответов, рекомендации, разделение говорящих и пользовательский
интерфейс в просмотренном коде не реализованы. Обработка часового файла
и фактическая работоспособность существующей цепочки требуют проверки.

## Предлагаемый сценарий первой версии

Все пункты этого раздела пока являются предложением.

1. Пользователь создаёт разбор, задаёт название и загружает запись.
2. Видит этап обработки и понятную причину ошибки, если она произошла.
3. Получает расшифровку и список вопросов с ответами кандидата.
4. Открывает вопрос: видит тему, ответ, его оценку, объяснение,
   удачные моменты и то, чего не хватило. Может найти фрагмент записи по времени.
5. Получает сводку по темам и список слабых мест с приоритетами подготовки.
6. Для слабых мест получает похожие тренировочные вопросы.

Предлагаемый начальный охват: один пользователь, русскоязычные технические
собеседования на Java-разработчика, локальный запуск, простой веб-интерфейс.
Регистрацию, оплату, многопользовательский доступ, мобильное приложение,
проведение собеседования в реальном времени и сравнение прогресса между
записями предлагается отложить. Эти границы ещё нужно согласовать.

## Предложения по качеству разбора

- Вопрос, ответ и выводы должны быть связаны с фрагментами расшифровки
  и временными метками. Модель не должна придумывать отсутствующие ответы.
- Оценка сопровождается критериями и объяснением. Шкалу и критерии
  согласуем отдельно; не сводим требования к одному числу.
- Если ответ неразборчив, оборван или невозможно определить говорящего,
  система отмечает недостаток данных и допускает отсутствие оценки.
- Нужно определить, как объединять уточнения и встречные вопросы,
  учитывать подсказки интервьюера и ответы, распределённые по записи.
- Рекомендация объясняет связь с конкретным пробелом. Источник вопросов
  (генерация, база или сочетание) ещё не выбран.
- Повторный анализ и исправления расшифровки обсуждаем до проектирования
  хранения результатов, чтобы не потерять исходные данные.

## Предлагаемая проверка готовности

Критерии ниже предварительные; численные пороги согласуем после замеров.

- Часовая запись проходит полный путь до отчёта; измерены время и стоимость.
- Вопросы и ответы сопоставлены с ручной разметкой нескольких записей.
- Оценки и объяснения сопоставлены с экспертным разбором; описаны расхождения.
- Проверены ошибки распознавания, неполные ответы и неясные роли говорящих.
- Ошибка отдельного этапа видна пользователю; определено поведение при повторе.
- Новый разработчик может запустить проект по документации.
