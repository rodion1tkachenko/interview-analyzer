# Что обсуждаем и что потом разрабатываем

Основание: [requirements.md](requirements.md). Сейчас уточняем требования,
код ещё не меняем. Отложенные функции в план не включаем.

## Сейчас: договориться, какой разбор нужен

### 1. Пользователь и результат — основное согласовано

- [x] Один пользователь: владелец приложения.
- [x] Java-собеседования, без выбора уровня вакансии.
- [x] Вопрос, ответ с временем, правильные моменты/ошибки/пробелы, оценка с объяснением.
- [x] Отложить топ, тренировочные вопросы и примеры хороших ответов.
- [ ] Решить, как указывать материалы для чтения.
- [ ] Решить, нужна ли общая сводка слабых тем.

Результат: конкретный состав отчёта без необязательных функций.

### 2. Договориться, как оценивать ответ — следующая тема обсуждения

- [ ] Выбрать шкалу и объяснить значения оценок.
- [ ] Решить, насколько важны полнота, правильность и объяснение причин.
- [ ] Решить, как учитывать подсказки и уточнения интервьюера.
- [ ] Определить, какие части собеседования оцениваем.
- [ ] Согласовать пример: вопрос → ответ → замечания → оценка → что почитать.

Результат: пример разбора, с которым согласен владелец. Он станет образцом
для разработки и проверки. Конкретный пример ещё не выбран.

### 3. Обсудить запись и удобство использования

- [ ] Решить, объединять ли основной вопрос и последующие уточнения.
- [ ] Обсудить ошибки распознавания и необходимость ручных исправлений.
- [ ] Выбрать интерфейс, поля загрузки, язык и необходимость истории.
- [ ] Согласовать внешний сервис, бюджет, время обработки и хранение.

Результат: понятен путь от выбора файла до готового разбора.

## Потом: задачи разработки

Это предварительный порядок. После обсуждения уточняем задачи и критерии
проверки. Выполняем их по указанию владельца.

### 4. Получить текст из реальной записи

- Проверить существующие сборку, тесты и запуск.
- Загрузить короткую, затем часовую запись через существующий API.
- Проверить текст, временные метки и статусы; измерить время обработки.
- Исправить обнаруженные проблемы, необходимые для согласованного сценария.

Готово, когда запись превращается в сохранённую расшифровку, а при сбое
видна причина. Скорость и качество проверены на примере.

### 5. Получить вопросы и ответы из текста

- Подключить выбранную модель и обработку длинной расшифровки.
- Выделять пары «вопрос интервьюера — ответ кандидата» с временем.
- Сохранять результат, проверять формат и обрабатывать сбои модели.
- Сверить список с ручным разбором записи.

Готово, когда вопросы и ответы можно сверить с записью по согласованным
правилам уточнений и ролей.

### 6. Добавить разбор каждого ответа

- Применять согласованные критерии и шкалу.
- Показывать правильные моменты, ошибки, пробелы и объяснение оценки.
- Добавить указания, что почитать, в согласованном формате.
- Проверить результат на примерах и спорных ответах.

Готово, когда есть четыре согласованные части разбора и помощь для
повторения темы; выводы можно сопоставить с ответом кандидата.

### 7. Сделать результат удобным для использования

- Реализовать согласованный способ загрузки, просмотра статуса и разбора.
- Добавить только согласованные функции истории, хранения и исправлений.
- Проверить полный путь от файла до результата.

Готово, когда владелец может самостоятельно загрузить запись и прочитать разбор.

### 8. Подготовить демонстрацию для диплома

- Сравнить разбор программы с ручным, описать расхождения.
- Зафиксировать время, стоимость и ограничения на часовой записи.
- Обновить инструкцию запуска и подготовить демонстрационный пример.

Готово, когда есть воспроизводимая демонстрация и результаты проверки качества.
